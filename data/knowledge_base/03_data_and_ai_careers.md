# Data and AI Careers

## The data career family
"Data" is not one job. The main roles differ in how much coding, statistics and business
context they require.

- **Data Analyst** — answers business questions with SQL, dashboards and basic statistics.
  Coding light, business heavy.
- **Business Intelligence (BI) Analyst** — builds reporting layers and dashboards (Power BI,
  Tableau, Looker). SQL plus one BI tool.
- **Data Engineer** — builds pipelines and data infrastructure (ETL/ELT, warehouses, Spark,
  Airflow). Heavy engineering.
- **Data Scientist** — models, experiments and statistical inference to drive decisions.
  Python/R, statistics, some ML.
- **Machine Learning Engineer** — puts models into production: training pipelines,
  deployment, monitoring. Software engineering plus ML.
- **AI / GenAI Engineer** — builds LLM applications: RAG, agents, evaluation, prompt and
  context engineering. A fast-growing, accessible entry point.
- **ML Researcher / Research Scientist** — advances methods; usually requires a PhD.

## Machine Learning Engineer vs Data Scientist vs AI Engineer
- **Data Scientist**: framing questions, experimentation, statistics, storytelling.
- **ML Engineer**: production systems, latency, reliability, scale, MLOps.
- **AI Engineer**: integrating foundation models into products — retrieval, prompting,
  tool use, guardrails, evaluation. Less maths than a data scientist, more product sense
  than a pure ML engineer.

## Core skills by role
- **Analyst:** SQL, Excel/spreadsheets, one BI tool, statistics intuition, communication.
- **Data Engineer:** Python, SQL, a warehouse (BigQuery/Snowflake/Postgres), orchestration,
  data modelling, cloud.
- **Data Scientist:** Python/R, pandas, scikit-learn, statistics and causal basics,
  experimentation (A/B testing), visualisation.
- **ML Engineer:** software engineering, PyTorch/TensorFlow, model serving, Docker, cloud,
  monitoring, CI/CD.
- **AI Engineer:** Python, embeddings and vector databases, RAG architecture, LLM APIs,
  prompt/context engineering, evaluation, basic backend (FastAPI).

## How to break in
1. **Pick a role, not "data".** The paths diverge quickly; choose based on whether you
   prefer business questions (analyst), infrastructure (engineer), statistics (scientist),
   production systems (MLE) or product integration (AI engineer).
2. **Build a public portfolio** of 2-3 end-to-end projects that mirror real work.
3. **Learn SQL deeply** — it is the single most transferable data skill.
4. **Show communication** — write up your projects as if explaining to a non-technical
   stakeholder.

## Portfolio project ideas
- Analyst: a dashboard from an open dataset answering a specific business question.
- Data Engineer: an automated pipeline that ingests an API and loads a warehouse daily.
- Data Scientist: an A/B test analysis with clear causal reasoning.
- ML Engineer: a model served behind an API with monitoring and a container.
- AI Engineer: a RAG application (for example a document Q&A or voice assistant) with a
  measurable retrieval and answer-quality evaluation.

## Realistic expectations
- Most "data scientist" postings in smaller companies are closer to analyst + some modelling.
- Deep learning roles usually expect a master's degree or strong research/engineering proof.
- AI engineering is one of the most accessible high-growth specialisations right now because
  much of the work is system design and integration rather than novel research.
- Generative AI fluency (retrieval, evaluation, agents, cost and latency trade-offs) is
  becoming a baseline expectation across data roles.

## Common mistakes
- Learning model architectures before learning SQL and business framing.
- Building only notebooks with no deployment or communication.
- Chasing the "sexiest" title (research scientist) without checking the credentials needed.
- Ignoring cloud and engineering basics, which gate most mid-level roles.
