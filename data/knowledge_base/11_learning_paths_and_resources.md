# Learning Paths and Resources

## How to design a learning path
A learning path is a sequence that takes you from "no skill" to "employable at a target
role". Build it from the job postings you are targeting, not from a generic course
catalogue.

Steps:
1. Collect 5-10 postings for the target role and list required skills.
2. Rank the skills by frequency and importance.
3. Sequence them from foundational to advanced.
4. Attach one concrete project to each skill to prove it.
5. Set a timeline and a public artefact for each stage.

## General principles
- **Projects over certificates.** Evidence of building beats completion badges.
- **Breadth then depth.** Get a working overview, then go deep in one area.
- **Feedback loops.** Ship, get feedback, iterate quickly.
- **Public learning.** Blog posts, repos and talks compound into visibility.
- **Consistency.** A few focused hours weekly beats sporadic cramming.

## Example path: AI / GenAI Engineer
1. Python fundamentals and clean code.
2. APIs, HTTP and one web framework (FastAPI).
3. Embeddings and vector databases; similarity search.
4. Retrieval-Augmented Generation (RAG): chunking, retrieval, grounding, evaluation.
5. LLM application patterns: prompting, context engineering, streaming, agents/tools.
6. Latency and cost optimisation; caching; async.
7. Deployment (Docker, a cloud platform) and monitoring.
8. Project: a deployed RAG app (e.g. a voice or document assistant) with a written
   evaluation of retrieval relevance and answer grounding.

## Example path: Data Analyst
1. Spreadsheets to an advanced level.
2. SQL (joins, aggregation, window functions).
3. Statistics intuition (distributions, significance, correlation vs. causation).
4. One visualisation/BI tool (Power BI, Tableau, Looker Studio).
5. Python/pandas for larger analysis (optional but valuable).
6. Project: an end-to-end analysis and dashboard answering a specific business question.

## Example path: Product Manager
1. Fundamentals of product, users and markets.
2. User research and interviewing basics.
3. Writing PRDs, user stories and acceptance criteria.
4. Prioritisation frameworks (RICE, impact/effort) and roadmapping.
5. Basic analytics and experimentation (A/B tests).
6. Technical literacy (APIs, databases, system basics).
7. Project: a product case study — problem, research, spec, metrics, trade-offs.

## Example path: Full-Stack / Software Engineer
1. One language deeply (Python, JavaScript, Java, Go).
2. Data structures and algorithms fundamentals.
3. Git, testing and debugging.
4. Web fundamentals and a framework; databases; APIs.
5. Deployment and cloud basics.
6. Project: a deployed full-stack app with tests and documentation.

## Free and low-cost resource categories
- **Documentation and official tutorials** for the tool you are learning (often the best).
- **Open courseware and MOOCs** for structured fundamentals.
- **Coding practice platforms** for algorithms and SQL.
- **Open-source repositories** to read real code and contribute.
- **Communities and Discord/Slack groups** for feedback and referrals.
- **Kaggle and open datasets** for data projects.

## Building a feedback loop
- Share work publicly and ask specific questions ("is my retrieval strategy sound?").
- Find a mentor or peer group; even one accountability partner helps.
- Use code review and design critique on your projects.
- Track outcomes: applications, responses, interviews — adjust based on data.

## A weekly study template
- 1 hour: review and consolidate notes (active recall).
- 3-5 hours: project work toward a real artefact.
- 1 hour: reading or a focused course module.
- 30 minutes: writing a short summary or update (public proof).
